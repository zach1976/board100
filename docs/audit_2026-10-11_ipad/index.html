iPad 界面审计 · 横屏与竖屏

2026-10-11 · 易用性 · iPad 操作习惯 · 12 种语言溢出与排版

结论：板子本身已经为 iPad 做过适配，板子以外的界面基本是拉宽的手机界面

12 种语言 × 6 种 iPad 尺寸（Pro 13 寸、mini 的横竖屏，分屏一半，侧拉）约 3450 次渲染，没有一处溢出报错。问题集中在大屏布局和 iPad 操作习惯上。

级别数量最要紧的
违规级1从训练计划打开板子后，返回键在两页之间无限循环，只能杀 app（手机上也有；代码已核实）
严重16不限宽：我的页、训练库、运行页、表单横跨 1000–1350 点；底部面板离开触发按钮；单运动 app 用手机底部标签栏；没有列表/详情分栏；横屏时步骤说明随场地转成竖排；没有任何键盘快捷键；没有 Apple Pencil 区分；横屏引导页底图只露三分之一且压住文字；iPad mini 和分屏下工具栏文字标签消失；11 个短字符串在 8 种语言里仍是英文
小问题约 17提示条盖住播放控件、球员编辑面板按钮偏小、无悬停和右键菜单、时间线两字母名字被截、旋转后滚动位置跳动等

已经做对的

  • 板子控件在 iPad 上放大，训练详情 900 点以上是两栏，首页内容列限宽 1000 点，底部面板限宽 640 点。
  • 旋转时状态保持；支持多任务；横竖屏下场地缩放都正确。

没能测到的

  • 分屏、侧拉、台前调度的实际窗口（只从代码判断），Apple Pencil、双指、触控板（模拟器做不出来），真机字体，大号辅助字体，VoiceOver。

模拟器实测：iPad 操作习惯与易用性

iPad UX audit: Tactics Board (HubBoard + VolleyballBoard), iPad Pro 13" M4 sim, iPadOS 27

Screenshots are in scratchpad/ipad_audit/ux/. Each has a full-resolution X.png and a downscaled X_s.png. Prefixes: p.. portrait, l.. landscape, r.. rotation tests. How landscape was obtained: real device rotation. A Cmd+Left/Right keystroke was sent to DeviceHub (osascript: activate DeviceHub, send key code 123/124 with command, then hand focus back to the previously frontmost app). No harness was used and no repo file was touched. git status is clean apart from the existing tactics_board/test/tmp_twoball_test.dart.

Overall verdict

The board itself is iPad-aware: chrome scales 1.4x, there is a two-pane drill detail at 900pt and wider, the home column is capped at 1000pt, rotation keeps its state, and the app supports multitasking (no UIRequiresFullScreen, all four orientations). The rest of the app is a stretched phone app. It has phone bottom sheets and a phone tab bar, no list/detail split, full-width forms and buttons, and no keyboard, pointer, Pencil or context-menu support. Two bugs are not iPad-specific but showed up in the walk. The worse one traps the coach in an endless back loop between the board and the session timer (BLOCKER).

Not tested / could not confirm

  • Split View / Slide Over / Stage Manager resizing. Not drivable from idb. From code: uiScale (toolbar.dart:69) and isTablet (home_page.dart:103) key off the window's shortestSide, so a 1/2-width split (about 678pt) keeps the 1.4x tablet chrome in a narrow window. The tools are Flexible, so they shrink rather than overflow. A short, wide Stage Manager window (shortest side under 600) switches to the phone-landscape rail. Needs a real-device pass.

Date: 2026-10-11. Read-only. No lib/ changes, no commits. The temporary tests (test/tmp_ipad_*.dart) have been deleted, and git status shows only the untracked tactics_board/test/tmp_twoball_test.dart, which was there before this audit.

How the sweep ran

  • Harness: one pumpWidget per file. EasyLocalization holds all 12 locales, and ctx.setLocale switches between them. The home widget is a ValueNotifier<Widget> inside a MaterialApp with the app's dark theme, and a ValueNotifier<TacticsState> supplies a fresh state per sport. Between screens the test calls navigator.popUntil(first) and then shows SizedBox.shrink().
  • Overflow capture: a hook on FlutterError.onError writes each overflow (locale, size, sport, screen, message, lib/ source line) to a TSV file. I checked the hook works by running the same sweep at 220×500 in Thai. It recorded 40 overflows, for example drill_library_page.dart:689 and toolbar.dart:1200.
  • View: device pixel ratio 2. Simulated safe area of top 24 and bottom 20. The real apps hide the status bar (UIStatusBarHidden), so the real top inset is smaller.
  • Fonts: Roboto and MaterialIcons from the Flutter cache, plus /System/Library/Fonts/Supplemental/Arial Unicode.ttf as the fallback font. CJK, Thai and Korean rendered as real text, with no tofu boxes. Metrics are Roboto/Arial rather than SF Pro/PingFang, so widths are close to iOS but not exact.

  • Shell artwork for sports other than soccer: served only from SoccerBoard. The other shells (volleyball, table tennis, water polo, rugby) have intro art only, and use the same _Backdrop code, so #1 applies to them. The hub intro (HubBoard art) was not rendered.

  • Practice plan was checked only in its empty state, with no saved plans in the list.
  • Not simulated: Stage Manager free-form window sizes, the iPad keyboard, and pointer hover. I also did not check the real safe-area insets on device, since the status bar is hidden.
