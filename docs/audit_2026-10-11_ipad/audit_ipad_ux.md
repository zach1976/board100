# iPad UX audit: Tactics Board (HubBoard + VolleyballBoard), iPad Pro 13" M4 sim, iPadOS 27

Screenshots are in `scratchpad/ipad_audit/ux/`. Each has a full-resolution `X.png` and a downscaled `X_s.png`. Prefixes: `p..` portrait, `l..` landscape, `r..` rotation tests.
**How landscape was obtained:** real device rotation. A Cmd+Left/Right keystroke was sent to DeviceHub (`osascript`: activate DeviceHub, send key code 123/124 with command, then hand focus back to the previously frontmost app). No harness was used and no repo file was touched. `git status` is clean apart from the existing `tactics_board/test/tmp_twoball_test.dart`.

## Overall verdict
The board itself is iPad-aware: chrome scales 1.4x, there is a two-pane drill detail at 900pt and wider, the home column is capped at 1000pt, rotation keeps its state, and the app supports multitasking (no `UIRequiresFullScreen`, all four orientations). **The rest of the app is a stretched phone app.** It has phone bottom sheets and a phone tab bar, no list/detail split, full-width forms and buttons, and no keyboard, pointer, Pencil or context-menu support. Two bugs are not iPad-specific but showed up in the walk. The worse one traps the coach in an endless back loop between the board and the session timer (BLOCKER).

## What works (no action)
- Drill detail uses two columns from 900pt (p07, l07).
- The home column is capped at 1000pt (l03).
- Overflow menus are anchored popups (p21, l20).
- The Share popover does not crash and shows correctly (p23). It is anchored at bottom-centre rather than at the button (`SharePlus` calls pass no `sharePositionOrigin`), which is cosmetic.
- State survives rotation with a sheet open (r04), mid-playback (r01/r02) and with a running timer (r05).
- Multitasking is enabled: `UISupportedInterfaceOrientations~ipad` has all 4 orientations, there is no `UIRequiresFullScreen`, and `UIApplicationSupportsMultipleScenes=false`.

## Not tested / could not confirm
- **Split View / Slide Over / Stage Manager resizing.** Not drivable from idb. From code: `uiScale` (`toolbar.dart:69`) and `isTablet` (`home_page.dart:103`) key off the window's `shortestSide`, so a 1/2-width split (about 678pt) keeps the 1.4x tablet chrome in a narrow window. The tools are `Flexible`, so they shrink rather than overflow. A short, wide Stage Manager window (shortest side under 600) switches to the phone-landscape rail. Needs a real-device pass.
- **Apple Pencil, palm rejection, two-finger pinch/pan, trackpad hover/right-click.** The simulator via idb cannot produce these. Findings 10 and 13 are from code. Pinch zoom is modal by design: the `InteractiveViewer` is only mounted in Zoom/presentation mode (`tactics_canvas.dart:1188`).
- **Ads on iPad.** No app-open ad appeared during the walk. The code has only full-screen formats (app-open, interstitial) and no banners, so there is no layout impact.
- **Accessibility tree loss (unconfirmed).** On two occasions, after the Timeline sheet and playback, `idb describe-all` returned only the application node until relaunch. A deliberate repro (open and close the Timeline) did not trigger it. This could be an app semantics issue or idb flakiness. Worth checking with VoiceOver on a device.
- **Rotation method side effect.** My first rotation attempt clicked DeviceHub's rotate button with `cliclick`. The user had already switched to Chrome, so the click landed on Chrome near a "启动 TerminalAssist" pill (about 1042,1033 pt). After that I switched to the keystroke method, which restores focus. The user may want to check that nothing was started by that click.
- The other project's simulator "Lang1000 Audit iPad" (F8AEB8A7) was never addressed. It showed Booted at start and Shutdown at the end, presumably changed by its owner.
